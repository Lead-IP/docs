title: "Enrich Company"
api: "POST /v1/enrich/company"
description: "Look up a client company's firmographics and send new values to review"
---

Looks up firmographics for one client company with the configured providers. Apollo is the only company provider, and each returned field names its source.

<Note>
  Required permission scope: `enrichment:write`, because this call can spend credits and read-only keys cannot make it. In Settings → API & Data, the API key dialog has an "Enrichment" permission group that grants it. Full Access includes it.
</Note>

<Warning>
  Company enrichment returns `no_match` unless the workspace stores its own Apollo key. Apollo is the only company provider, and without your own key it is skipped as `resale_not_allowed`. Store the key in Settings → API & Data before you rely on this endpoint.
</Warning>

## What happens to the result

Nothing is written onto the record. New values for blank fields become a pending proposal in the review queue, under Enrichment review → Companies. A person approves them field by field in LeadLex. Only the workspace's client companies are touched. The workspace's own company is never changed.

## Providers and licensing

Apollo's license does not let LeadLex serve its data to your workspace on LeadLex's key. Without your own Apollo key, the call returns `no_match` for free, and `providers` shows `{ "name": "apollo", "outcome": "skipped", "reason": "resale_not_allowed" }`. Apollo is never called in that case. With your own Apollo key, Apollo runs on it and the values come back with `source: "byok"`.

## Billing

A request that returns results (`proposed` or `found`) costs at most 1 credit. Nothing is charged for `nothing_new`, `no_match`, errors or skipped providers. Phone does not apply to companies.

| Outcome | Credits |
|---------|---------|
| `proposed` or `found` on LeadLex's key | 1 |
| Every delivered value came from your own key (`source: "byok"`) | 0 |
| `nothing_new`, `no_match`, any error, or Apollo skipped as `resale_not_allowed` | 0 |

Credits are reserved first, then settled. Before any provider runs, the request reserves the most it can cost (1), and only if a provider running on LeadLex's key could supply the fields. When only your own key or a skipped provider could supply them, nothing is reserved. If the balance is too low, the call returns `402 insufficient_credits` before any provider is called. The unused part is refunded once the result is known, and everything is refunded on failure. `credits_used` in the response is the final amount. Allow up to 60 seconds for a response. Providers share a 40 second budget.

## Bring your own provider key

Workspace admins can store their own Apollo or A-Leads key in Settings → API & Data, under "Your own data provider keys". The key is write-only: after saving, the app shows only "Set · ends in XXXX" and the date, never the key itself. When a key is stored, that provider runs on it for this workspace.

Values that come from your own key return with `source: "byok"` and a `provider` field that names the vendor. They cost 0 credits. In `providers`, a step that ran on your key carries `byok: true`.

## Request

### Headers

```
Authorization: Bearer wbk_your_api_key
Content-Type: application/json
```

<ParamField header="Idempotency-Key" type="string">
  Optional. A retry with the same key returns the stored 200 response and is not charged again. Two requests sent at the same time with the same key can both run, so send retries one after another.
</ParamField>

### Body Parameters

<ParamField body="company_id" type="string">
  ID of an existing client company in the workspace. Send exactly one of `company_id` or `domain`.
</ParamField>

<ParamField body="domain" type="string">
  Company domain, for example `acme.com`. A URL is accepted and reduced to its host. Send exactly one of `company_id` or `domain`. If several companies share the domain, the call returns `409 ambiguous_record`.
</ParamField>

<ParamField body="create" type="boolean" default="false">
  Create the company when none matches. Only allowed together with `domain`.
</ParamField>

<ParamField body="name" type="string">
  Name for a newly created company. Only used with `domain`.
</ParamField>

<ParamField body="fields" type="string[]">
  Which fields to look up. Any subset of `website`, `domain`, `industry`, `size`, `linkedin_url`, `logo_url`, `description`, `city`, `state`, `country`, `street` and `postal_code`. Default: all.
</ParamField>

### Statuses

| Status | Meaning |
|--------|---------|
| `proposed` | New values for blank fields wait in the review queue |
| `found` | No record matched and `create` was false. The values are returned only and nothing is stored |
| `nothing_new` | Every requested field was already filled, or nothing found was new. 0 credits |
| `no_match` | No provider found the company, or every provider was skipped. 0 credits |

## Ambiguous matches

If more than one company has that domain, the call returns `409 ambiguous_record` with `data.candidates[]`, each with an `id` and a `name`. Nothing is charged. Retry with the `company_id` of one candidate.

## Errors

Errors use the standard error envelope, `{ "error": { "code", "message" } }`. Responses marked refunded say "No credit was used." unless the automatic refund failed. In that case the message asks you to contact support with the request id.

| Status | Code | When | Credits |
|--------|------|------|---------|
| 400 | `validation_error` | Bad body: both or neither of `company_id` and `domain`, a bad email, domain or id, empty or unknown `fields`, `create` not a boolean, or `create` sent with an id | 0 |
| 401 | (auth) | Missing or invalid API key | 0 |
| 402 | `insufficient_credits` | The balance is below the reservation ("needs up to N credits") | 0 |
| 403 | `insufficient_permissions` | The key lacks `enrichment:write` | 0 |
| 403 | `subscription_inactive` | The workspace subscription is not active | 0 |
| 404 | `not_found` | `company_id` is not in this workspace, or not visible to the key owner | 0 |
| 409 | `ambiguous_record` | Several records share that domain. `data.candidates` lists `{ id, name }` | 0 |
| 429 | (rate limit) | The per-key daily limit was reached | 0 |
| 500 | `create_failed` | `create: true` but the record could not be created | Refunded |
| 500 | `internal_error` | The proposal could not be saved | Refunded |
| 502 | `upstream_error` | Every provider that was called failed. `data.providers` has the trace | Refunded |
| 503 | `service_unavailable` | No enrichment provider is configured at all | 0 |
| 503 | `review_not_set_up` | The review queue is not installed in this environment | 0 or refunded |
| 503 | `billing_unavailable` | Credits could not be checked | 0 |
