---
title: "Enrich Email"
api: "POST /v1/email/enrich"
description: "Find a person's work email from their name and company domain"
---

Finds a work email for one person. A free people search runs first. It must match exactly one person with that name at that domain, and only then is the email revealed.

<Note>
  `POST /v1/enrich/email` is an alias with the same contract. Required permission scope: `enrichment:write`, because this call can spend credits and read-only keys cannot make it.
</Note>

## Billing

The call costs 1 credit only when the provider returns a verified email that the workspace does not already have. These cases are refunded: no email found, an unverified email, or an email already in the CRM. The response shows what happened in `charged` and `refunded`.

## Request

### Headers

```
Authorization: Bearer wbk_your_api_key
Content-Type: application/json
```

<ParamField header="Idempotency-Key" type="string">
  Optional. A retry with the same key replays the stored 200 response without a second charge. Two requests sent at the same time with the same key can both run, so send retries one after another.
</ParamField>

### Body Parameters

Send one of these three shapes.

<ParamField body="first_name" type="string">
  First name. Use together with `last_name` and `domain`.
</ParamField>

<ParamField body="last_name" type="string">
  Last name. Use together with `first_name` and `domain`.
</ParamField>

<ParamField body="full_name" type="string">
  Full name. Use together with `domain` instead of `first_name` and `last_name`.
</ParamField>

<ParamField body="domain" type="string">
  Company domain, for example `acme.com`. A URL is accepted and reduced to its host. The person must be on this domain, and a different domain never matches.
</ParamField>

<ParamField body="document_id" type="string">
  Document ID from `POST /v1/prospector/search`, in the format `member_id_company_id`. Use it alone, without a name or domain.
</ParamField>

Name matching ignores case, accents and punctuation in any script.

import requests, uuid

headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json",

## Ambiguous matches

If several people share the name at that domain, the call returns `409 ambiguous_person` with `data.candidates[]`, each in the same shape as `person`. Nothing is charged. Retry with the `document_id` of one candidate.

## Errors

Errors use the standard error envelope.

| Status | Code | Description |
|--------|------|-------------|
| 400 | `validation_error` | The body does not match one of the three shapes |
| 402 | `insufficient_credits` | The workspace has no credits left |
| 404 | `person_not_found` | Nobody with that name at that domain. No charge |
| 409 | `ambiguous_person` | Several matches. Retry with a candidate's `document_id`. No charge |
| 502 | `upstream_error` | The data provider failed. The credit is refunded unless the error message says the refund failed |
| 503 | `service_unavailable` | Email enrichment is not available |
| 504 | `upstream_timeout` | The outcome is unknown. Check your credit balance before retrying |
