---
title: "Reveal Prospect"
api: "POST /v1/prospector/reveal"
description: "Reveal the work email for one prospect found via search"
---

<Warning>
  The change dated 2026-10-22 removed phone and name fields from reveal. The response now returns the email and its verification state only. Reveal is also billed now.
</Warning>

Required permission scope: `prospects:write`, because this call can spend credits and read-only keys cannot make it.

## Billing

Billed the same way as [Enrich Email](/api-reference/email/enrich): 1 credit only when the provider returns a verified email that the workspace does not already have. No email, an unverified email, or an email already in the CRM is refunded.

## Request

### Headers

```
Authorization: Bearer wbk_your_api_key
Content-Type: application/json
```

<ParamField header="Idempotency-Key" type="string">
  Optional. A retry with the same key replays the stored 200 response without a second charge. Send retries one after another, because two requests sent at the same time with the same key can both run.
</ParamField>

### Body Parameters

Send `document_id`, or `member_id` with an optional `company_id`. All come from [Search Prospects](/api-reference/prospector/search).

<ParamField body="document_id" type="string">
  Document ID from search results, in the format `member_id_company_id`
</ParamField>

<ParamField body="member_id" type="string">
  Member ID from search results. Use when you do not send `document_id`
</ParamField>

<ParamField body="company_id" type="string">
  Company ID from search results. Optional
</ParamField>

## Response

<ResponseField name="data" type="object">
  <Expandable title="properties">
    <ResponseField name="email" type="string | null">The work email, or `null` when none was found</ResponseField>
    <ResponseField name="email_status" type="string | null">Status reported by the provider</ResponseField>
    <ResponseField name="verification" type="string | null">`verified`, `unverified` or `null`</ResponseField>
    <ResponseField name="email_verified" type="boolean">Whether the email is verified</ResponseField>
    <ResponseField name="already_in_crm" type="boolean">Whether the workspace already had this email</ResponseField>
    <ResponseField name="charged" type="boolean">Whether a credit was charged</ResponseField>
    <ResponseField name="refunded" type="boolean">Whether the credit was refunded</ResponseField>
  </Expandable>
</ResponseField>

<CodeGroup>

```bash cURL
curl -X POST https://data.leadlex.com/functions/v1/api-gateway/v1/prospector/reveal \
```

```python Python
import requests

API_KEY = "wbk_your_api_key"

    "document_id": "123456_7890"
})
print(response.json())
```

## Errors

| Status | Code | Description |
|--------|------|-------------|
| 400 | `validation_error` | Missing `document_id` or `member_id` |
| 402 | `insufficient_credits` | The workspace has no credits left |
| 403 | `insufficient_permissions` | Missing `prospects:write` permission |
| 502 | `upstream_error` | The data provider failed. The credit is refunded unless the error message says the refund failed |
