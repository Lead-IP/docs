---
title: "Enrich Contact"
api: "POST /v1/enrich/contact"
description: "Look up a contact's professional data and send new values to review"
---

Looks up professional data for one contact with the configured providers. The providers run in the order Apollo, then A-Leads, and each returned field names its source.

<Note>
  Required permission scope: `enrichment:write`, because this call can spend credits and read-only keys cannot make it. In Settings → API & Data, the API key dialog has an "Enrichment" permission group that grants it. Full Access includes it.
</Note>

## What happens to the result

Nothing is written onto the record. New values for blank fields become a pending proposal in the review queue, under Enrichment review → People. A person approves them field by field in LeadLex. Only contacts in this workspace are matched: not archived, not merged, and not private to another member.

## Providers and licensing

- A-Leads supplies the verified email (verified only), the phone (opt-in), LinkedIn, job title and company.
- Apollo's license does not let LeadLex serve its data to customer workspaces, so Apollo appears in `providers` as `{ "name": "apollo", "outcome": "skipped", "reason": "resale_not_allowed" }`. It is never called and costs nothing.

## Billing

Phone is opt-in and off by default. A delivered phone costs 10 credits. Otherwise a request that returns results (`proposed` or `found`) costs 1 credit. Nothing is charged for `nothing_new`, `no_match`, errors or skipped providers. Credits are charged per request, never per field.

| Outcome | Credits |
|---------|---------|
| `proposed` or `found`, no phone delivered | 1 |
| `proposed` or `found` with a phone | 10 |
| Phone asked for but not found, other fields delivered | 1 |
| `nothing_new`, `no_match`, any error, or providers skipped as `resale_not_allowed` | 0 |

Credits are reserved first, then settled. Before any provider runs, the request reserves the most it can cost (10 with phone, otherwise 1), and only for fields that a provider could supply. When only skipped providers could supply the fields, nothing is reserved. If the balance is too low, the call returns `402 insufficient_credits` before any provider is called. The unused part is refunded once the result is known, and everything is refunded on failure. `credits_used` in the response is the final amount. Allow up to 60 seconds for a response. Providers share a 40 second budget.


## Request

### Headers

```
Authorization: Bearer wbk_your_api_key
Content-Type: application/json
```

<ParamField header="Idempotency-Key" type="string">
  Optional. A retry with the same key returns the stored 200 response and is not charged again. Two requests sent at the same time with the same key can both run, so send retries one after another.
</ParamField>

### Body Parameters

<ParamField body="contact_id" type="string">
  ID of an existing contact in the workspace. Send exactly one of `contact_id` or `email`.
</ParamField>

<ParamField body="email" type="string">
  Email of the contact to look up. Send exactly one of `contact_id` or `email`. If several contacts share the email, the call returns `409 ambiguous_record`.
</ParamField>

<ParamField body="create" type="boolean" default="false">
  Create the contact when none matches. Only allowed together with `email`.
</ParamField>

<ParamField body="first_name" type="string">
  First name for a newly created contact. Only used with `email`.
</ParamField>

<ParamField body="last_name" type="string">
  Last name for a newly created contact. Only used with `email`.
</ParamField>

<ParamField body="full_name" type="string">
  Full name for a newly created contact, as an alternative to `first_name` and `last_name`. Only used with `email`.
</ParamField>

<ParamField body="fields" type="string[]">
  Which fields to look up. Any subset of `job_title`, `linkedin_url`, `profile_picture_url`, `company`, `website`, `industry`, `city`, `state`, `country`, `office_address`, `email` and `phone`. Default: all except `phone`. Phone is opt-in and off by default. A delivered phone costs 10 credits.
</ParamField>

### Statuses

| Status | Meaning |
|--------|---------|
| `proposed` | New values for blank fields wait in the review queue |
| `found` | No record matched and `create` was false. The values are returned only and nothing is stored |
| `nothing_new` | Every requested field was already filled, or nothing found was new. 0 credits |
| `no_match` | No provider found the person, or every provider was skipped. 0 credits |

## Ambiguous matches

If more than one contact has that email, the call returns `409 ambiguous_record` with `data.candidates[]`, each with an `id` and a `name`. Nothing is charged. Retry with the `contact_id` of one candidate.

## Errors

Errors use the standard error envelope, `{ "error": { "code", "message" } }`. Responses marked refunded say "No credit was used." unless the automatic refund failed. In that case the message asks you to contact support with the request id.

| Status | Code | When | Credits |
|--------|------|------|---------|
| 400 | `validation_error` | Bad body: both or neither of `contact_id` and `email`, a bad email, domain or id, empty or unknown `fields`, `create` not a boolean, or `create` sent with an id | 0 |
| 401 | `missing_auth` or `invalid_key` | Missing or invalid API key | 0 |
| 402 | `insufficient_credits` | The balance is below the reservation ("needs up to N credits") | 0 |
| 403 | `insufficient_permissions` | The key lacks `enrichment:write` | 0 |
| 403 | `subscription_inactive` | The workspace subscription is not active | 0 |
| 404 | `not_found` | `contact_id` is not in this workspace, or not visible to the key owner | 0 |
| 409 | `ambiguous_record` | Several records share that email. `data.candidates` lists `{ id, name }` | 0 |
| 429 | `rate_limited` | The per-key daily limit was reached | 0 |
| 500 | `create_failed` | `create: true` but the record could not be created | Refunded |
| 500 | `internal_error` | The proposal could not be saved | Refunded |
| 502 | `upstream_error` | Every provider that was called failed. `data.providers` has the trace | Refunded |
| 503 | `service_unavailable` | No enrichment provider is configured at all | 0 |
| 503 | `review_not_set_up` | The review queue is not installed in this environment | 0 or refunded |
| 503 | `billing_unavailable` | Credits could not be checked | 0 |
